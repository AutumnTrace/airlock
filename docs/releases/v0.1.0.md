First release.

airlock wraps an MCP server that speaks the stdio transport and sits between it and the client.

It records:

- the whole session to a hash-chained JSON Lines log, with optional Ed25519-signed checkpoints;
- every tool definition the server lists, pinned in memory or in a lockfile.

It enforces, with a TOML policy:

- allow and deny rules by tool name;
- path, pattern and length constraints on arguments;
- validation against each tool's own `inputSchema`;
- per-tool rate limits;
- redaction of credentials in results.

A tool whose definition changes after it was pinned can be hidden from the client, and calls to it refused.

Commands: `wrap`, `verify`, `keygen`, `check`, `view`.

The viewer is published at https://autumntrace.github.io/airlock/ with two recorded sample sessions: server-filesystem under a deny-by-default policy, and a rug pull being caught. Both are signed with the demo key in `docs/samples/demo.pub`.

Supports MCP 2026-07-28 (stateless `server/discover`, `resultType`) and earlier revisions back to 2024-11-05, including JSON-RPC batches.

Binaries for Linux, macOS and Windows on amd64 and arm64 are attached, with checksums and a build provenance attestation:

```sh
gh attestation verify airlock_0.1.0_linux_amd64.tar.gz --repo AutumnTrace/airlock
```
