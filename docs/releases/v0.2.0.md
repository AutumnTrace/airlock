New command: `airlock diff`, for reviewing a server upgrade before you accept it with `--repin`.

```sh
airlock diff old.lock.json new.lock.json
```

It compares two lockfiles tool by tool and lists added, removed and changed tools. For each changed tool it shows:

- a word diff of the description, using the same LCS diff as the viewer, so the terminal and the viewer agree on what changed;
- a line diff of the rest of the definition, with two lines of context;
- the description heuristics run on every added or changed tool. Flags the old definition already had are marked, so the new ones stand out.

Tag characters and zero-width or bidi characters are written out (`‹tags:"…"›`, `‹U+200B›`), because a terminal would show nothing for them.

Exit codes follow diff(1): 0 the pins are the same, 1 they differ, 2 a lockfile is missing or unreadable. A pin whose stored sha256 doesn't match its definition, as in a hand-edited lockfile, gets a warning.

To make the second lockfile, run the upgraded server under airlock with `--lock` naming a file that doesn't exist yet. Diffing against a live server directly is still open in #11.

Binaries for Linux, macOS and Windows on amd64 and arm64 are attached, with checksums and a build provenance attestation:

```sh
gh attestation verify airlock_0.2.0_linux_amd64.tar.gz --repo AutumnTrace/airlock
```
